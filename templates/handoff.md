# 交接单模板（.team/handoff/<成员名>.md）

成员上下文变重、任务簇结束、或要换人时，由**离开的成员**写（它已经不在时由 Lead 根据任务记录写），新成员的 brief 里附上路径。

```
交接人：<成员名> → 接手人：<成员名>
负责过的任务：task-N, task-M（状态各是什么）
改过的文件和原因：路径 —— 一句话
没做完的：具体到下一步动作
踩过的坑：试过但不行的方法和原因（避免新人重踩）
关键事实：代码里不容易看出来、但必须知道的（隐式约定、奇怪的依赖、测试的特殊跑法）
验证方式：怎么确认它现在是好的（命令和期望输出）
```

## 什么时候换人

- 一个成员连续做完一个任务簇（通常 3–5 个相关任务），下一个任务簇换新成员。
- 成员自己报告上下文很重、开始遗忘早先的约定，或者回报质量明显下降。
- 同一个任务退回超过 2 次（换个视角往往比继续磨更快）。
- 里程碑之间默认换一批实现者；评审员可以保留一个里程碑，保持标准一致。
