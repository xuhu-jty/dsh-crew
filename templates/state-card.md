# 状态卡模板（项目根目录 `AGENTS.local.md`）

DHS 会把项目根的 `AGENTS.local.md` 自动注入给**每一个** agent（Lead 和所有成员）：会话开始时注入，上下文被压缩后重新注入，文件被改后推送新版。所以它是"忘了就会出事"的那几条事实的唯一可靠位置。

规则：
- **40 行以内**。只写当前事实和硬规则；细节链接到 `.team/STATE.md` / `PROJECT.md`，不复制。
- Lead 维护。每次用户拍板、里程碑变化、复盘新增规则后更新；改了 `.team/STATE.md` 却没改它，插件会在收工前拦下。
- 不写过程、不写历史（历史在 `PROJECT.md` 履历）。
- 建议加进 `.gitignore`：`*.local.md` 是本机状态，不是交付物。

```markdown
# <项目名> · 状态卡（Lead 维护，40 行以内）

你在一个用 project-team skill 推进的项目里工作。以下是当前事实和硬规则，优先于你的记忆。

## 现在
- 最后更新：<时间>
- 阶段：<需求 / 方案 / 设计 / M<N> 进行中 / M<N> 等验收 / 已交付>
- 当前里程碑目标：<一句话>
- 下一步：<具体到动作>
- 等用户回答：<问题，或"无">

## 已拍板（不要再问，不要推翻）
- <决定> —— <一句原因>
- …

## 必须
- 改代码后跑 `<verify 命令>` 并看结果；没跑不许说通过。
- <复盘沉淀出的项目规则>

## 禁止
- 用任何方式绕过被拒绝的操作（插件拦截、审批、权限）。被拦就停下报告。
- <例：改根 pom.xml 必须串行，同时只能一个任务动它>
- <复盘沉淀出的项目规则>

## 授权
- 提交：<每次弹窗批准 / 里程碑验收后用户创建 .team/commit-authorized>
- 推送、改历史、删分支：每次单独问用户。

## 详情
`.team/STATE.md`（完整状态）· `PROJECT.md`（目的、方案、决定、履历）
```
