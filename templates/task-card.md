# 任务卡格式（写进 team_task_create 的 description）

`subject`：动词开头的一句话，例如"实现订单列表接口的分页"。

`description`：

```
目标：这个任务完成后，用户/系统能做到什么（一句话）
背景：相关的 PROJECT.md 章节、方案里的决定、上游任务的产出（给路径）
验收标准：
  - 可检查的条件 1（怎么检查：命令 / 测试名 / 页面操作）
  - 可检查的条件 2
不做：明确不在本任务范围内的东西
写入范围：与 write_scopes 一致的路径
要更新的文档：README / PROJECT.md / DESIGN.md / CHANGELOG.md 中的哪一节，或"无行为变化"
界面（有的话）：遵守 DESIGN.md；新功能放在信息架构的哪个位置
方法钥匙：1–3 把（可选，复杂或高风险任务必填）：<钥匙名 (English)> —— 大白话解释 —— 在本任务里具体要求什么（例如"有限状态机：医嘱状态只能按状态表迁移，非法迁移抛错并有测试"）；出处 plain-to-meta 分册路径或经典来源
完成后交给：reviewer / qa / 下一个任务的负责人（成员名）
```

`blocked_by`：真正需要先完成的任务 id。
`write_scopes`：会改的文件或目录前缀，和描述里一致。
